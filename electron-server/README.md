# electron-server

Автономный aiohttp-сервер на Python (`server.py`) — **не** ComfyUI `PromptServer`.
Заменяет его для standalone Electron-приложения. Слушает `127.0.0.1:8765` по
умолчанию.

Пути роутов идентичны оригинальным ComfyUI-адресам этого аддона
(`/fl_cosyvoice3/...`), поэтому фронтенд работает без изменений кода — достаточно
настроить `API_BASE` (см. `web/fl_common.js`).

## Запуск

```
python server.py
```

Обычный системный Python, **без** torch/ML-зависимостей — только `aiohttp`.

## Эндпоинты

- `/fl_cosyvoice3/browse/list_dir` — листинг файловой системы для диалогов
  выбора файла/папки.
- `/fl_cosyvoice3/script_editor/{read,write}` — чтение/запись текстовых файлов.
- `/fl_cosyvoice3/script_library/*` (12 роутов) — проект аудиокниги: акты,
  скрипты, роли, хэши строк, склейка аудио (`stitch_lines`), удаление аудио,
  замена спикера и т.д.
- `/fl_cosyvoice3/vo_dub/*` (6 роутов) — VO Dub проекты (CSV-датасет игровой
  локализации): дерево бакетов, строки, пометка ролей устаревшими, применение
  аудио-эффектов.

## `/fl_cosyvoice3/render/line` — прямой синтез (без ComfyUI)

Новый POST-эндпоинт, встроенный поверх `_tts_engine.py` (модульная версия
доказанной в `tts_prototype.py` последовательности вызовов). Синтезирует
одну строку напрямую через vendored `cosyvoice` (`AutoModel` +
`inference_instruct2`), без очереди/графа ComfyUI, и кладёт WAV туда же,
куда его ждёт существующая логика "озвучена ли строка" (`expected_path`).

Тело запроса:

```json
{
  "folder": "C:/path/to/project",
  "base_name": "chapter_01",
  "position": 1,
  "speaker": "monetochka",
  "instruct": "спокойным, тёплым тоном рассказчика",
  "text": "Текст строки для синтеза."
}
```

Ответ: `{"ok": true, "path": "...", "hash": "...", "duration_s": 4.36,
"sample_rate": 24000}` либо `{"error": "..."}`.

Модель CosyVoice кэшируется в памяти между запросами (загрузка медленная),
поэтому первый вызов на процесс — медленный, следующие — быстрые.

Как и `stitch_lines`/`apply_effect`, `torch`/`cosyvoice` импортируются лениво
и **только внутри** обработчика — если этот процесс `server.py` запущен
обычным системным Python без ML-стека, эндпоинт корректно вернёт
`{"error": "synthesis failed: No module named 'torch'"}` вместо падения
сервера. Чтобы эндпоинт реально работал, `server.py` нужно запускать тем
Python-окружением, где установлены `torch`+`cosyvoice` (сейчас это венв
ComfyUI, см. `_tts_engine.py`'s `FL_COSYVOICE3_DIR`) — выбор этого
окружения для Electron-дистрибутива остаётся решением Этапа 4.

Живьём проверено: реальный `.wav` (4.36с/24000Hz, ненулевая амплитуда),
второй вызов подряд быстрее первого (кэш модели сработал), и корректная
JSON-ошибка под обычным системным Python.

## tts_prototype.py

Изолированный прототип, доказавший, что синтез речи FL-CosyVoice3 можно
вызвать **напрямую**, вообще без ComfyUI. Логика перенесена в
`_tts_engine.py` и используется эндпоинтом выше; сам файл оставлен как
самостоятельный скрипт для быстрой проверки окружения (`python
tts_prototype.py`) в отрыве от HTTP-сервера.

## Известные ограничения

`soundfile`/`numpy` не установлены в обычном системном Python по умолчанию —
эндпоинты `stitch_lines` и `apply_effect` в этом случае корректно возвращают
JSON с ошибкой вместо падения сервера.
